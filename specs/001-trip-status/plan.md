# Implementation Plan: Trip Status, ETA and Delay Communication

**Branch**: `codex/a3-v1` | **Date**: 2026-11-07 | **Spec**: [spec.md](spec.md)

**Input**: `/specs/001-trip-status/spec.md`, generated through the installed
Spec Kit 1.3.2 Codex specify workflow before implementation.

## Summary

Build a small static browser application for one fictional rider and two trip
legs, with rider/dispatch views of one consistent state. Separate a pure domain
transition module from the DOM and storage adapter. Mock time/channels explicitly;
retain traceability to the eight A3 goals. Publish an immutable V1 snapshot and
preserve model/spec/plan/tasks/source together.

## Technical Context

**Language/Version**: Modern JavaScript ES modules, semantic HTML5, CSS; Node.js 24
for built-in tests, a static development server and deterministic asset copy.

**Primary Dependencies**: No application/runtime packages; Node standard library
only for development. Spec Kit 1.3.2 installed separately in task-local tooling.

**Storage**: One versioned JSON document in localStorage, scoped to browser profile
and origin. Web Locks serialize read/compare/write commands; revision rejects stale
editors. Storage events refresh other tabs. If storage or locks are unavailable,
explicit single-tab temporary mode is used; no multi-tab atomicity is promised.

**Testing**: Node `node:test` scenario/invariant tests plus browser interaction,
responsive, keyboard and same-origin-tab checks. Tests are explicitly requested by
this plan/spec verification contract; they do not author Step 4/6 findings.

**Target Platform**: Current Chromium/Edge/Firefox/Safari over HTTPS, or HTTP
localhost for development. No reliance on `file:` storage behavior.

**Project Type**: Static web application with buildless assets copied to `dist/`.

**Performance Goals**: Two legs and small demo histories; local actions must render
without page navigation. No external font/image/network calls in the app.

**Constraints**: 375 px responsive layout; keyboard and visible status support;
no real messages or personal information; two tab consistency only when browser
storage and Web Locks are available. No authentication claim for the view selector.

**Scale/Scope**: One demo rider, two legs, four journeys, eight goals. No backend,
real GPS, route solver, account system, financial workflow or production concurrency.
